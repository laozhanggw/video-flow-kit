# 对标视频深度拆解

## 目标

把一条或一组真实对标视频拆成两种资产：

1. **证据层**：视频实际出现了什么，在哪个时间点出现，来自画面、声音、字幕、标题、简介或评论的哪一类证据。
2. **行动层**：下一条视频必须学什么、可以借什么、不能照抄什么、制作时怎样验收。

最终要回答的不是“这个视频为什么爆”，而是：

> 它让观众完成了什么观看任务？它用哪些可观察的机制让观众继续看？哪些机制可以迁移到当前项目？

播放量、点赞量和作者自称的爆款只能作为结果信号，不能单独证明任何机制造成成功。

## 适用范围

适用于：

- YouTube Shorts 对标视频；
- 阳台、猫舍、空间改造、宠物安全、家居和生活方式视频；
- 收到一个视频链接、下载视频、Storyboard、字幕、评论或对标拆解聊天记录；
- 在写脚本、分镜、图片或视频提示词之前做市场表达校准。

不适用于：

- 只判断视频技术上能不能使用；
- 只审核生成视频是否有畸变；
- 没有原片证据、只凭标题或截图推断完整结构；
- 直接照抄某个作者的角色、台词、镜头或人设。

## 强制顺序

### 阶段 0：定义本轮问题

先写清：

- 当前项目、平台、画幅和目标用户；
- 本轮要学习的是选题、开头、结构、节奏、真实感、声音、标题还是完整制作方式；
- 对标样本是否与当前项目具有相同的用户问题、空间约束和观看任务；
- 本轮不做什么，例如不因一个样本直接升级频道规律，不直接写生成提示词。

### 阶段 1：建立原片证据

优先读取原视频和所有可用独立证据：

- 视频技术元数据；
- 时间轴和抽帧；
- 关键动作附近的密集抽帧；
- 字幕或口播转写；
- 环境音、动作声、BGM和声音变化；
- 标题、简介、标签和封面；
- 评论区，优先看高赞评论，也要抽查普通评论和批评评论。

不要把稀疏抽帧当作逐帧观看。无法确认时标记 `U1 无法确认`。

证据标记：

- `F1 原片直接事实`
- `F2 多模态一致推断`
- `C1 评论区观众原话/主题`
- `M1 公开结果信号`
- `H1 用户提供线索`
- `V1 观众心理或效果推断，待验证`

### 阶段 2：拆解观看任务，而不是只拆镜头

先用一句话写：

> 观众点开后，最想确认什么？

然后拆成：

1. 初始状态：观众看见什么问题或愿望；
2. 风险/冲突：为什么不能继续保持原状；
3. 过程承诺：视频暗示接下来会解决什么；
4. 中段奖励：每个时间段给观众什么新信息；
5. 结果验证：是否真的解决了开头问题；
6. 情绪落点：观众最终是放心、惊喜、治愈、满足、好奇还是怀疑。

### 阶段 3：原子级时间线

按事件边界拆，不按固定秒数硬切。每一行至少记录：

- 开始/结束时间；
- 画面事实；
- 人物或宠物动作；
- 表情、视线和身体状态；
- 场景与空间关系；
- 道具新增、移动、固定、消失或状态改变；
- 镜头景别、机位、运动、剪辑方式；
- 字幕/口播；
- 环境音、动作声、BGM；
- 这一段给观众的新信息；
- 它兑现的是哪一个承诺；
- 证据等级和不确定项。

特别标记：

- 首帧是否已经有冲突；
- 重要动作用了多少真实时间；
- 哪些动作被快剪或蒙太奇压缩；
- 哪些关键状态用独立静态镜头展示；
- 每个剪辑点是落在动作中、反应中还是静止画面；
- 结果是否通过实际使用而不是成品空镜证明。

### 阶段 4：提取六类可迁移机制

#### A. 需求机制

- 真实用户是谁；
- 用户想完成什么任务；
- 痛点是安全、功能、舒适、审美、身份还是情绪；
- 评论是在回应问题、结果、人物善意，还是只回应视觉刺激；
- 是否存在租约、预算、物业、承重、天气、宠物安全等现实约束。

#### B. 开头机制

- 0–1 秒看见什么；
- 0–3 秒是否能静音读懂问题；
- 冲突是危险、失败、反差、欲望、悬念还是人物关系；
- 是否先给结果、先给问题、先给人物反应；
- 开头是否已经暗示结尾奖励。

#### C. 结构和情绪机制

- 谁受益、谁行动；
- 情绪如何逐段变化；
- 是否有后怕、失败、重新尝试或发现隐藏问题；
- 施工动作是否服务于问题解决；
- 开头暴露的每个问题是否有结尾验证；
- 是否有“局部改善冒充完整解决”的硬伤。

#### D. 节奏和剪辑机制

- 各段实际时长分布；
- 长镜头承担什么，短切承担什么；
- 哪些动作必须给够时间才能看懂；
- 哪些重复动作被压缩为蒙太奇；
- 硬切、叠化、静态展示、动作接动作分别承担什么功能；
- 中段是否每隔一段就出现新状态、新道具、新风险或新结果。

不要把“前三秒留人”误读成“全片每三秒硬切”。

#### E. 真实感和视觉机制

- 是否像真人手机、DV、朋友拍摄或专业纪录；
- 构图是否故意不完美；
- 是否有自动对焦、轻微晃动、过曝、动态模糊、生活痕迹；
- 人物是否有自然的小动作、视线、停顿和失误；
- 空间状态是否连续；
- AI 破绽是否影响核心情绪或只是表现层瑕疵。

#### F. 声音和包装机制

- 标题承诺了什么；
- 简介如何定义人群、问题和结果；
- 口播是讲故事、点名约束、解释因果还是制造情绪；
- 环境音和动作声是否帮助观众理解物理事件；
- BGM 如何控制情绪弧；
- 评论区是否由结尾问题引导；
- 封面/首帧是否在手机小尺寸下清楚表达问题或结果。

## 评论区分析规则

至少分开看：

- 情绪回应：害怕、感动、放心、喜欢；
- 需求回应：我也有这个问题、我需要这个方案；
- 行动回应：怎么做、材料、预算、租约；
- 真实性回应：AI、假的、空间变化；
- 风险/伦理回应：不安全、虐待、消防、植物有毒、物业许可；
- 结果回应：猫真的使用、空间真的可用。

评论主题只表示观众说了什么，不自动表示所有观众都这样想，也不能等同留存或转化。

## 输出物

每次完成一个对标样本，至少输出：

1. `01_原片事实时间线.md`
2. `02_观看任务与结构机制.md`
3. `03_剪辑声音标题包装拆解.md`
4. `04_评论区需求与反对信号.md`
5. `05_可迁移生产合同.md`

如果是多个样本，再增加：

6. `06_样本对照与候选规律.md`

## “可迁移生产合同”必须写什么

它不是提示词，而是交给制作对话框的验收合同，必须包含：

- 当前项目要复制的观看任务；
- 必须保留的开头信息；
- 必须出现的情绪转折；
- 必须出现的中段新奖励；
- 结尾必须验证的结果；
- 可以借鉴的剪辑节奏和声音职责；
- 可以借鉴的真实感表现；
- 不能照抄的表面元素；
- 当前项目的现实硬伤；
- 每个问题对应的视觉证据；
- 生成前停止条件；
- 发布后要观察的指标和评论关键词。

每条规则按以下格式写：

```text
规则：
适用范围：
什么时候使用：
具体动作：
为什么：
正例：
反例/失败：
不能照抄：
来源：
证据状态：
下一步验证：
```

## 对改造类视频的终局检查

任何空间改造视频进入脚本或生图前，必须建立：

```text
开头问题
→ 观众担心的后果
→ 中间解决动作
→ 终局必须达到的空间状态
→ 终局实际使用动作
→ 观众情绪兑现
```

逐项检查：

- 开头暴露的风险是否全部在终局解决；
- 上方、下方、侧面、门口、边缘和动线是否都检查；
- 安全、隐私、遮阳、防水、收纳、噪音等功能是否真的恢复；
- 终局是否只是“看起来好看”，还是能够实际使用；
- 施工动作是否都推动状态变化；
- 是否存在局部修复冒充完整修复；
- 结尾是否仍然留下核心疑问。

任何一个核心问题没有对应验证镜头，结论必须是“修改后再制作”。

## 最终决策

只能给出以下三种之一：

- `可以进入结构设计`
- `补证据/改剧情后再进入结构设计`
- `不建议制作`

不得因为对标视频播放量高，就直接判断当前题值得做。

## 证据边界

- 一条样本只能形成案例观察；
- 两到四条可比样本只能形成待验证候选规律；
- 五条以上可比样本重复出现，才可写阶段性规律；
- 交给制作对话框前必须合并为 V3 的“可迁移生产合同”；当前口径以 `D:\自己开发的程序\AI视频全流程提示词_直接使用版_v3\13_矛盾清单与冲突处理机制.md` 为准；
- 本频道发布结果只能说明本次结果，不能自动证明因果；
- 对标评论区和公开数据不能替代本频道 Studio 数据；
- 如果原片、声音或评论无法读取，必须写明缺口及其影响。

## 交付前自检

- [ ] 没有把表面元素当核心机制；
- [ ] 没有把播放量当因果证据；
- [ ] 没有把对标的特殊场景硬套到当前项目；
- [ ] 时间线有证据等级和不确定项；
- [ ] 中段每个关键段都有新信息或新状态；
- [ ] 开头问题与结尾验证一一对应；
- [ ] 真实感、剪辑、声音、标题和评论区都被检查；
- [ ] 写出了不能照抄的内容；
- [ ] 生成前有明确停止条件；
- [ ] 结论区分事实、推断、假设和待验证。
