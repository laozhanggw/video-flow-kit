# 自适应视频生产

目标：用最短总用时，把小分镜变成可发布的素材。观众看得懂、情绪和功能兑现，是唯一验收标准。图数、抽卡数、生成秒数、利用率都只是诊断信号。

**这些信号只能用来发现问题，不能用来做决定。** 它们和「一盒装不装得下」冲突时，一律以装得下为准。实测过一次：一盒写了两件事，第二件一次都没生成出来，而图数、秒数、取用率全部正常——事后指标看不见丢件。

## 渠道参数（唯一登记处）

| 项目 | 值 | 用法 |

## 语言（用户 2026-09-28 定，硬规则）

- 所有提示词（制卡词、视频正文、声音描述、禁止项）一律用**简体中文**写。用户要能看懂每一句。不要因为“模型对英文更好”自行改成英文；用户明确要求某一条用英文时才例外，且只改那一条。
- 人物台词、口播、旁白**保持小分镜里的原语言，逐字照抄，不翻译**。英文口播就写英文原句，放进中文正文的引号里，例：妈妈大声喊：“Lily, stop! Not in the water!” 翻成中文是严重错误。
- 修复、改写、换语言重写时，台词原文不动。改了台词必须是用户明确要求。

## 四种输入，各管一件事

| 名称 | 是什么 | 何时用 |
|---|---|---|
| 参考卡（图） | 同一人物/空间/阶段的多视图卡，可带简短中文标签 | 默认；人物卡管身份，空间卡管建筑，阶段卡管当前状态 |
| 生产卡（文字） | 上传哪几张、各借什么、完整视频正文、设置、输出名 | 每个生产单元一张 |
| 单幅首帧（图） | 锁定视频开头的一个时刻 | 工具只支持首帧、构图必须锁死，或出现关键几何错误时 |
| 续接截帧（图） | 前段视频里的实际姿态 | 同一动作必须无缝延续时 |

默认路径是“共用参考卡＋当前动作文字→视频”。叙事先后、施工先后都不产生尾帧依赖；只有无缝动作才等截帧。依据：用户 2026-09-14 鸽子项目实战“提速特别多”，2026-09-23 窗改项目“几乎没有浪费”。

## 你是谁：总控还是子任务

- 用户直接开的对话就是**总控**。只有总控面对用户：收反馈、做决定、改快照、派子任务、每轮结束告诉用户下一步。用户不需要提醒你开子任务或检查，第 7 步规定的时刻你都要主动做。
- 任务里写着“写词子任务”“检查子任务”“修复子任务”时，你是**子任务**。只读给定的快照和单元卡，写回文件就结束，不和用户讨论，也不改快照。
- 用户有问题一律找总控。子任务出的错由总控检查发现，派修复。

## 工作流程

接手先读项目快照的最新 R 号和台账里的最新有效记录。项目文件夹里没有快照，就是新项目，从第 1 步开始，在该文件夹里建快照和台账。已确认的剧情、设置、接受状态直接复用。查不到又影响执行的缺口，集中问一次；缺口只阻塞依赖它的那次提交，规划和写正文照常推进。

### 1. 定终局

用户给的是已确认的完整小分镜、末尾附《移交生产表》时：终局、锁定项、阶段路线、人物物件直接抄进快照，N 清单就是第 2 步的输入；不重新设计剧情，只检查能不能拍，拍不了的列给用户改。否则：
先写清观众在等什么、最后人物怎样使用空间（几个人坐、桌上放什么、通道在哪）、哪些动作和硬时间锁死。功能闭环缺失时读 [输入与终局](references/intake-and-end-state.md)。多个单元共享一个逐步变化的空间时，读 [阶段规划](references/state-planning.md)，先定终局布局和必要阶段，再决定做哪些卡。

### 2. 筛分镜、定单元

每个小分镜给一个结论：保留、并入相邻动作、降为可选过渡、删除。判断标准只有一条：观众静音能否看出新信息或必要的情绪/功能停留。

然后合并。同一人物、空间和时间里能自然连下来的动作放进一条（例如“搬入→放下”）。满足以下任一条件才拆：可选时长装不下、构图或物理条件不兼容、实测超载、用户要求单独交付。

**一条生成内部装 6–7 刀（13–15 秒装满），每一刀只有一种运镜、一条动作线。刀没有最小时长——1 秒也行**（阿初的 15 秒组就是 2/2/2/3/5/1，`阿初的油管库.md` L4550）。**刀数是除出来的，不是规定值：生成秒数 ÷ 2。** 写出 2–4 刀的盒子，等于每刀 4–7 秒，那一刀里必然有 3 秒无事可做。 Seedance 的公开规范写「单条提示词只写 1 种运镜，多镜头必闪屏 / 割裂」——那条约束的是**一条运镜里塞多个机位**，不是禁止写切点。实测 2026-10-27：写明「近景 0.55 m 俯拍 → 硬切 → 全景 1.45 m 略仰」，一帧切干净（F00053→F00054，无过渡帧），机位不漂；**只挪机位、不换景别的"切"才漂**——观众看不见那个切，模型就当成一条连续长镜头演下去。判据与写法见 [内部硬切](references/internal-cut.md)。

**装多满由秒数决定，不由件数决定：13–15 秒 ÷ 2 秒 = 6–7 刀，装满为止。**（2026-10-27 实测：12 秒盒子里写“搬第一个 + 搬第二个 + 两趟推车”，第二个动作一次都没生成出来——但那是因为**搬一个墩要 4–5 秒，12 秒装不下三个 4–5 秒**，不是“件数超过 2”。同一批 15 秒装 5 刀、6 刀都没有这个问题。**限制是总时长装不装得下，不是件数。** 原来那句「一盒最多两件事，三件以上一律拆」是错的归因，已撤。）

**还有一条更硬的：一条生成只能装一个地点的一件事。动作里出现「从 A 走到 B 再放下」，必须拆成「起手镜头 ＋ 落点镜头」，中间硬切。** 理由是模型记不住人物手里拿着的东西——人一走远，手里的物体就被丢掉。同一件事试了 5 次，最后一次只写一个动作、8 秒给足、措辞全对，**独轮车和墩照样在人物走远时消失**。这不是措辞、时长或负载问题，是能力边界。判据和拆法见 [一次一个地点](references/one-location-per-shot.md)。

**这一步要顺手过一遍每个小分镜：这条能不能一次生成做完？** 不能的当场标「拆两镜」，不要先划完单元再去试。

**分镜表里的一「段」是剪辑结果，不是拍摄内容。** 母版写「4.633 秒，拆掉旧栈道，旧板被撬起搬走，两岸清出裸土」，那是几十分钟的活剪成 4.6 秒。照抄成一次生成，等于要求模型 4.6 秒拆完 9 米桥面约 60 块板——物理上不成立，改多少措辞都不成立。**落笔前先算一遍：这一段里人手的自然速度，要不要超过这一段的秒数？** 超过就按时间跳跃在段内切刀，每刀只演一个能自然做完的片段（撬起一块板 2.2 s ＋ 硬切 ＋ 桥面已空 2.4 s）。观众接受时间跳跃，因为母版就是这么剪的；不接受的是「4.6 秒演完几十分钟」。细则见 [内部硬切](references/internal-cut.md)。

反过来，一盒只装一件事、生成 4 秒、成片取 2.5 秒，是一盒一件的正常样子，不要因为“生成秒没用满”就硬加内容。

**换机位、换工序、风险高、需要独立验收、"状态变了"，都不算拆分理由**，因为合并后可以用内部硬切表达（每刀一机位一动作，刀间换景别，切点写成「硬切，一帧完成，不许推拉摇渐变」）。真正的拆分理由只有上面那四种。

时长从动作推：先估动作和必要停留要几秒、预计可剪几秒，再选最近的档位。**时长按动作自然完成的时间给足，成片秒数靠剪辑拿**，不要为了让生成秒贴近成片秒数而压缩动作。细则见 [分镜与生成单元](references/shot-vs-generation-unit.md)、[提示词密度](references/prompt-density-and-merging.md)。已生成的素材保留，新方案只安排剩余内容。

### 3. 先交生产总图

参考卡阶段确定后，先交一张总图，再展开生产卡。总图回答四件事：

- 每个小分镜归哪个单元，合并理由是什么。
- 每个单元传哪几张图，每张负责什么（身份/空间/当前阶段/材料/目标），哪些已有、哪些待制。
- 每张待制卡的父图、完整制卡词、输出名、服务哪些单元。
- 关系图：`小分镜 → 单元 → 图/制卡词 → 视频词 → 视频`。实线表示真实输入依赖，虚线表示归属或硬切。

格式见 [台账规范](references/production-ledger.md) 和 [台账模板](templates/production-ledger.md)。台账、快照和单元卡放在同一个项目目录里，一个项目只有一本台账。单元多时，总图的内容直接落进 [项目快照](templates/project-snapshot.md) 的单元表和图片职责表，不另写一份。

### 4. 选卡、制卡、查冲突

按 [参考图策略](references/reference-image-policy.md) 执行。优先复用现有的人物、建筑和阶段卡；只在信息不够时补卡，已知缺的视角可以提前补。一张卡只画同一对象、同一阶段，多个视图之间几何要相容。

上传前逐张打开实际图片核对。如果一张卡上显眼地画着本段还不该出现的东西（未来的顶部、家具、完成地板），就去掉这张、换一个合适的视图，或者局部补图。靠文字写“只借局部”压不住图像。

### 5. 空间合同（凡是换机位、安装、跨内外的单元都必做）

内外翻转已经在两个项目里出现过：一次是网内外颠倒，一次是外挑框架跑进室内。所以这类单元写视频正文之前，先写四行：

- **锚点**：2–4 个所有机位都不变的原建筑（墙面、门、栏杆、窗洞），用它们描述方位，不写“画面左/右”。
- **关系**：新构件在锚点的哪一侧、附着在谁身上；操作者站哪边，都不改变构件所在的面。
- **状态**：起点有什么 → 谁通过可见接触改变了什么 → 终点仍然没有什么。
- **证据视点**：哪个镜头证明了功能（能坐、能挡、能通过）。

参考卡和正文都要服从这四行。生成后静音看一遍，先确认锚点关系没变。

**分工：锚点管「内外、附着在哪一面」，画面坐标管「远近、长条贯穿、这一头有没有」。** 两套不许混着用——写"远端/近端/两端/全长"一律改成画面坐标，细则见 [空间怎么写](references/space-wording.md)。

### 6. 写生产卡

按 [提示词与时间转译](references/prompt-and-performance.md) 写。顺序按 Seedance 的权重规范排（越前面权重越高，稳定约束和负面词放最后）：

1. 每张图借什么。
2. 当前阶段、站位、哪些还没完成。
3. 从贴近有效动作的可信起点开场（道具已在手、人已到位，但来处合理）。动作写「慢、连贯」：缓慢转身、缓慢蹲下、动作轻柔流畅、无僵硬感。
4. 谁接触什么、产生什么可见变化。
5. 接下一个有效信息或必要停留。
6. 相机：**逐刀写机位**（焦段＋高度＋角度＋固定），相邻两刀景别必须不同；每处切点单独一行写「⚠️硬切至镜头N：一帧完成，不许推拉、不许摇、不许渐变、不许叠化、不许闪白」。一刀之内只写一种运镜。
7. 声音。
8. **稳定约束（必写，固定一行）**：`面部与人体结构正常、五官清晰不崩坏、动作连贯不僵硬、衣物与发型一致、背景不闪烁、画面无割裂、人物与手持物件全程不消失。`
9. **负面词（必写，两串分开）**：先抄稳定串 `画面闪烁、卡顿、跳帧、变脸、变形、穿模、肢体畸形、多手指、模糊、重影、色彩断层、人物消失、动作不连贯`，再写本项目的内容串（不要出现第二个人、不要出现文字等）。

第 8、9 条不是可选项。缺了它们，模型收不到「别崩、别丢」的指令——本项目实测丢过整辆独轮车和一个混凝土墩，负面词里当时没有「人物消失」这一条。

真实感先靠参考图本身：普通住宅尺度、使用痕迹、自然光。正文只写当前景别看得见的细节。

声音按“动作—声源—时间”写：可见动作配短促同步声，底下垫一层低环境声；情绪停留可以写克制的无歌词纯音乐，并写清何时进、何时退。无对白、环境声、动作声、配乐是四个独立选择，分别写明。

时间分三层写：成片预算、生成时长、素材内节奏。“成片取 1.6 秒”说的是剪辑，生成时让动作自然完成。

**要表达位置和距离时，按 [空间怎么写](references/space-wording.md) 写：禁用「两端/对岸/全长/近端/远端/另一头」，改用「画面最下缘/画面最上缘」＋两端点名＋数量＋米数。** 这条有 4 次失败、1 次成功的实测记录，不是偏好。

要落到文件的生产卡，格式一律按第 7 步末尾的固定格式（程序读取的单元卡和说明文件分开写）。用户只想自己试生成时，只给上传图、设置、可复制正文和一个观察点。要全片或交接时，给总图加完整卡：[标准说明](templates/standard-generation-card.md)，复杂几何再加 [关键镜头说明](templates/high-risk-generation-card.md)。

### 6b. 有台词或旁白的单元

遇到口播或旁白时：

- 正文里写出台词原文，不写“此处加台词”。台词语言按上面“语言”一节：原语言逐字照抄，不翻译。
- 按台词字数估出说话时长，再加上动作和停顿的余量，一起决定单元时长。台词装不下就拆单元，不压语速。
- 写清语气、重音和停顿。模型默认读得很平，这些要明确写出来。
- 口型同步不可靠时，用构图避开嘴部（侧脸、背影、手部、远景），或者改成画外旁白。

2026-09-28 阳台积水项目首次实用：英文口播被写成中文，是严重错误，已由“语言”一节约束。时长估算等其余做法仍按 [抽卡与停止](references/sampling-and-stop-rules.md) 继续记录。

### 7. 调度：文件驱动，短上下文并行

单元数 ≥4，或用户要求并行时，按 [文件驱动生产](references/file-driven-production.md) 做。要点：

- 信息只存文件：[项目快照](templates/project-snapshot.md)（冻结的“做成什么”，含共享块和已知坑）、台账（进度和实际文件）、每单元一张单元卡。对话随时可关，新对话读文件接着干。
- 共享块（画面规范、人物、空间、风格光线、环境底声）只在快照里写一次，每条正文原文照贴。子任务只写本单元专属的阶段、动作、接触、镜头和动作音效。
- 每个写词子任务只拿快照 + 负责的单元卡，不给历史对话。按阶段分组，相邻单元放同一组，每组 2–4 个单元。写词子任务不占生成名额。
- 按轮次批处理：定快照 → 批量制卡并附验收清单，用户一次审完 → 子任务并行写词 → 新上下文做提交前检查 → 用户一次生成全部视频、一次汇总问题 → 只修有问题的单元。
- 反馈写回文件：单元问题升单元卡 v 号，通用问题写进快照“已知坑”并升 R 号。
- 由总控主动推进：第 2 步单元一定完就数单元、宣布走哪种方式；每轮结束用三行告诉用户刚做完什么、要用户做什么、下一轮是什么。开不了子任务时，把要让用户新开的窗口和每个窗口要发的话一次给全。总控自己对话过长时，主动建议换新总控并给出开场话术。细则见 [文件驱动生产](references/file-driven-production.md) 第 9 节。

3 个及以下单元可以由总控直接写，但仍然先写快照。多条生产线同时推进时，另见 [并行规则](references/parallel-production.md)。用户说“一次给齐”时，按 [一次性交付协议](references/one-shot-handoff.md) 冻结当前快照版本，交齐所有已确定单元。正文一律写完整，不写“同上”或占位符。

用户按约定把文件放进可用目录，就算接受。AI 没看过的素材，不写“已审”。

提示词定稿后交给自动生产程序，不让用户手工复制。最终交付一律按 [交给自动生产程序](references/auto-production-table.md)（2026-10-06 定稿，硬规则）输出，这一步只适配现有导入程序的输入格式，不改程序、不改已确认内容：

- `共用卡制卡词.md`：所有图片任务，每节 `## RC01｜名称` → `生产状态：` → `父图：` → `输出：生成\RC01_名称_v01.png｜模型｜比例｜清晰度｜画质档` → 唯一 ```text。模板 [共用卡制卡词](templates/shared-card-prompts.md)。
- `单元\U01.md`：每条视频一个文件，只有标题、五行头部（本卡版本/生产状态/生成/上传顺序/输出文件名）和 `## 拼好的完整正文` 下唯一 ```text。模板 [单元卡](templates/production-unit-card.md)。
- `说明\`：分析、空间合同、专属部分、版本记录、历史和待确认事项，程序不读。模板 [单元说明](templates/production-unit-notes.md)。
- `导入核对清单.md`：逐条任务＋统计＋十项自检，每次必交。模板 [导入核对清单](templates/import-checklist.md)。

路径一律写 `项目文件夹\准确文件名` 或 `项目文件夹\生成\RC编号_名称_v01.png`；状态只写定稿或草稿；参数全部显式填写。不碰 Excel、不改程序和台账。能运行导入器就只做离线解析验证，不能运行就写“已按格式逐项检查，未实际运行导入器验证”。直接交付标准文件和核对清单，不只给框架。

### 8. 局部修复

读 [抽卡与停止](references/sampling-and-stop-rules.md)。达到观看任务就停。失败时先定位是哪一层出的问题：目标、输入冲突、单元超载、提示词漏写、工具能力、声音。只修这一层，已可用的片段保留。同一个错误出现两次，就换输入、构图或负载，不要继续换词重抽。换个单元也会出现的错误，写进快照“已知坑”。偏差按 [变更短记录](templates/production-change-log.md) 记，结果按 [结果简记](templates/review-result.md) 记。

## 常见错误

| 错误 | 正确做法 |
|---|---|
| 每段都先做一张首帧图 | 共用参考卡直接生视频 |
| 按分镜编号排尾帧链 | 硬切各自准备，只有无缝动作才等截帧 |
| 为凑档位把 1 秒动作拉到 5 秒 | 合并相邻动作，或只取可用短段 |
| 一盒只装 2 刀，或反过来硬塞三件事 | 两种都错：**按 13–15 秒 ÷ 2 秒 = 6–7 刀装满**。刀少＝每刀被拉长，多出来的时间是傻站；塞不下＝总时长不够。判据看总秒数能不能装下，不看件数 |
| 生成 12–15 秒的大单元 | **生产档位 13–15 秒，标准做法**（2026-10-27 起）；一棵树/一道工序单独成盒反而会做长刀 |
| 让一个镜头完成“从这头搬到那头” | 拆起手镜头＋落点镜头，中间硬切；模型记不住手里的东西，人一走远就丢 |
| 一条生成内部把多刀写成一条连续长镜头 | 每刀一机位一动作，刀间硬切，且必须换景别；切点单独一行写「硬切，一帧完成」 |
| 两刀景别相同、只挪机位就以为切了 | 必须换景别（近 ↔ 中 ↔ 全）；同景别同机位的切观众看不见，模型会当成一条连续长镜头 |
| 把母版一段「4.6 秒拆完整座桥」直接当成一次生成 | 母版一段是剪辑结果；按时间跳跃在段内切刀，每刀只演一个能自然做完的片段 |
| 一段写着 4.6 秒但需要 30 秒的活，靠"生成秒给足"硬做 | 算人手自然速度要不要超秒数；超了就切刀，不是加时长 |
| 为了"这一刀别太静"往里加过渡动作（擦汗／直起腰／后退半步／看一眼成果／把工具戳在地上／走过来站住） | **先翻小分镜这一刀的「那一个动作／接触对象／终点状态」，只有这三处写了的才能进提示词。** 实测 2026-10-27：U04＋U05 两盒 23 秒里 5.9 秒（26%）是这么加出来的，小分镜一处都没有，成片里就是白走 |
| 状态变化在切点上，却从"完成之后"开始写（桥已铺满、他走在桥上） | 写「完成那一下」：最后一块板还端在手里，放下去、锤敲两下。起手＝必须看见那一下的前 0.3 秒 |
| 分镜写「脚步还没停」就写成"走过来再转身" | 分镜那半秒只值两声脚步。明写「只许原地并一下步（约 0.4 秒）就停住」并否掉「不许先走一段」；实测写成走位模型会给 2.5 秒 |
| 靠给某一刀加秒来控制节奏 | 秒数是建议值，模型会漂（写 2.8 秒实出 4.6 秒）。节奏靠刀数和刀的内容，能写住的只有"没有多余动作可做" |
| **让一刀要求一个"上一刀画面里没有、这一刀内又做不完"的状态** | **内容层失败的头号原因。** 模型不会停下来问你，它会自己编一段过渡把它填上——走过去、搬东西、站着，全是废动作。实测：U04 第 3 刀要"桥面铺满"（上一刀只演了一块板），模型让他抱着长木条站在空桥上；U05 第 4 刀要"她在桥心"（上一刀她在校车台阶上），模型让她走回去 2 秒。**合法出口只有三个：上一刀已经看见／这一刀演得完／结果镜头静态重新起手** |
| 一盒塞四个工序（架梁＋铺板＋立栏杆＋铺碎石） | 每一刀都在跳状态，有效取用率掉到 65%。**一盒一工序**：18 秒生成拿 12.5 秒可用（约 70%），多花 3 秒但多拿回 2.7 秒，且不用重抽。塞得越满，废得越多 |
| 相邻两刀"都写了全景"，以为换了机位就是切 | 切点两侧实际画幅相同，观众看不见这个切，模型会连成一条推近长镜头（U05 第 1→2 刀实测：2.208 的切点两侧都是全景，近景一直到 4.875 才靠推近出现） |
| 写"只拍腰以下的近景" | 模型不会"一进来只有腿"，实测两次都失败。要表现"手没扶栏杆"改用全景＋手明显垂在身侧，或俯拍桥面只拍脚与栏杆的关系 |
| 用"这个动作成片里会不会被剪掉"当判据 | **这条判断不了。** 剪辑台的决定写卡时无法预判，视频模型也看不到这句话。换成可查的两条：① 这一刀要交代的事写成 6 字短句，和前刀一样就删一刀（阿初：拖沓＝传达同样信息的重复镜头，L3359）② 按"发生了什么变化"切段，有"没变化"的段就是空的 |
| **拿分镜的「成片秒」当生成秒用** | 分镜那一栏是**剪完的长度**，不是拍摄长度。成片 4.7 秒的"40 块板铺满"，一个人真做要 10–12 秒。**生成秒要按素材秒定，长出来的剪掉**（阿初 15 秒生成、13 秒成片，L4622）。按成片秒生成 = 每个动作被压在自己那一格里做不完 = 模型补走位 = 废动作 |
| **按单刀卡取用率 60%** | **数学上不成立。** 平台单段最少 4 秒，成片 <2.4 秒的刀用 4 秒生成必然低于 60%（转头 0.834 秒→20.8%、立栏杆 2.033 秒→50.8%、末镜 1.920 秒→48%）。按刀卡会强制这些刀**跨工序并进别的盒子**，而跨工序合并必然产生状态跳跃——10-27 U04 那盒四道工序就是这么来的。**取用率只在盒级考核，目标 87%（阿初 86.7% 也是组级数字）** |
| 把「中间段时长 ÷ 工序数 ≥ 对标×0.9」当成生成密度要求 | 这条只管**成片看起来不像"浅浅收拾了一下"**，跟拍摄要几秒无关。拿它压素材秒，等于让一个人在 0.5 秒里做完 10 秒的活 |
| **把"对标那一段几秒"当成"自己要拍几秒"** | 对标的成片是「AI 生成之后再加速」剪出来的。它 4.7 秒的铺板，你照着拍 4.7 秒，一个人铺不完 40 块 —— 模型只能补走位。**素材秒按 `references/material-seconds.md` 算**（起手 0.5 ＋ Σ动作单位 ＋ 收尾 0.5），成片秒＝Σ素材×0.867，是结果不是约束 |
| 把一段"一个人做不完的活"写成一条镜头，靠"演着演着就完成了" | 一刀的定义是「一个人能连续做完的一个动作片段」。**判据：按"发生了什么变化"切段，有"没变化"的段就是不合格**，必须拆成两刀、中间硬切 |
| 把取用率目标定成 100% | 阿初自己 15 秒生成、13 秒成片，取用率 86.7%（L4622）。**目标 87%**；允许的 13% 是节奏剪切（2 秒剪成 1.5 秒），不是人物白走 |
| 禁止项写成「不要出现绳索栏杆」，把开头的对照物一起杀掉了 | 禁止项必须**写清是"新的那个"还是"旧的那个"**。2026-10-27 U04 实测：为防止新栏杆被画成绳索，写了「不要出现绳索栏杆」，结果连旧钢索一起去掉——而分镜明写「钢索不得在这一刀消失（它是开头的证据）」。改成「**新栏杆**做成绳索／铁艺／横板」＋「**旧钢索**被拆掉、被拉直」 |
| 生成 12–15 秒的大单元 | **生产档位 13–15 秒，标准做法**（2026-10-27 起）。一个工序单独成盒反而会把那一刀拉长到 4–5 秒，出傻站 |
| 负面词只写「不要出现第二个人」这类内容禁止项 | 稳定串（闪烁/变形/穿模/人物消失）＋内容串，两串都写 |
| 动作写成「把墩搬过去」 | 写成慢动作序列：缓慢弯腰、双手扣住、缓慢抬起，并加稳定约束 |
| 搬东西那条反复改词重抽 | 同一个动作改到第二遍没成就换镜头语言（拆两镜），不要改到第五遍 |
| 写“两端/对岸/全长/近端/远端/另一头” | 改成“画面最下缘/画面最上缘”＋两端点名＋数量＋米数 |
| 指望多视图卡画对“相隔很远的两头” | 多视图卡只管单个对象的形体；空间关系靠正文，参考图用单幅透视图 |
| 只写“水泥墩”，不写形状和“不是什么” | 写六面平整有棱角、有凹槽，并明写“不是圆柱、不是水泥管、不是塑料桶” |
| 用长串“禁止”压制冲突的参考图 | 换图、限定职责或补局部图 |
| 只写“手机感”来追求真实 | 先修参考图的尺度、痕迹和光线 |
| 把计划文件名当成已有的图 | 计划路径必须有对应的上游 RC 任务、输出名逐字一致；没有上游任务就是缺口，标草稿 |
| 单元卡里混入分析、版本记录、多个 text 块，或给机器字段换名字 | 单元卡只留标题＋五行头部＋`## 拼好的完整正文`；其余写进 `说明\` |
| 上传顺序写“人物图、场景图”或“同上” | 写 `1 名称 = 项目文件夹\准确文件名.png`，编号连续 |
| 交付只给框架，让用户自己整理 | 直接交标准文件＋`导入核对清单.md` |
| 一个局部失败就重做全片 | 只补失败单元，共享卡不动 |
| 在一个长对话里逐条写全部提示词 | 写快照，按组开短上下文子任务并行写 |
| 每条正文各自描述人物和空间 | 共享块原文拼接，只写专属部分 |
| 等图出来再写视频词 | 制卡词附验收清单，用户审图；偏差只改受影响的词 |
| 生成一条修一条 | 按轮次批量生成、批量汇总问题、批量修 |
| 修改只说在对话里 | 写回单元卡或快照，升版本号 |
| 写词的对话自己检查自己 | 新上下文对照清单做提交前检查 |
| 等用户提醒才开子任务 | 到了第 7 步的时刻，总控主动开，并告诉用户 |
| 让用户去和子任务对话里沟通问题 | 用户只找总控；子任务写完就结束 |
| 提示词写成英文 | 一律简体中文；用户要求英文才改那一条 |
| 把英文口播翻成中文 | 台词按小分镜原语言逐字照抄 |
| 手穿玻璃、穿模就改词、加禁止词 | 先剪、再重抽 1 次，仍有才改构图或动作 |
| 对话被压缩了还不提醒换总控 | 压缩过一次就写台账，并给出新总控开场话术 |
