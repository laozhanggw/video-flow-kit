# 并行生产：总控、工作对话与共享素材

## 目标

把生成等待变成并行时间。优先服务按时做出可反馈的视频，不把每个片段当艺术品精修。

前提是 [全片关键阶段](state-planning.md) 已给本批任务共同依据。普通多参考下，共用人物/建筑卡完成后，必要阶段多视图卡可分别准备；各视频只等自己的必需输入，不等全片制卡完成，也不默认等前片尾帧。共享卡只有一位指定制作者，单元生产卡直接引用有效卡，不附带默认逐条首帧任务。

## 两种并行，分开算

| 类型 | 是什么 | 规则 |
|---|---|---|
| 写词子任务 | Codex 自动开的短上下文，只写单元卡正文 | 按 [文件驱动生产](file-driven-production.md)：只给快照+单元卡，同时最多 4 个，不占生成名额 |
| 制作对话 | 用户在其中实际提交生成、等待、回传结果的对话 | 按下面的名额规则 |

写词子任务交回的单元卡，就是制作对话的执行依据。制作对话不重写正文，只按卡提交、回传结果。子任务由总控主动开，用户只和总控沟通，见 [文件驱动生产](file-driven-production.md) 第 9 节。

## 同时开多少制作对话

- **默认上限：1个总控＋最多3个活跃制作对话。**容量未知时先用2个制作对话；只有1条独立就绪线就用1个，不凑数量。简单项目可由同一对话兼任总控和制作。
- 这里的3是试用管理设置，不是任何平台的技术极限，也不是已实测的最优值。用户可以明确调整上限；实际安排还受工具并发/限额、用户可同时操作数量和就绪独立线数量约束，取较小值。不知道平台容量就查已有设置或说明未知，不虚构允许多路生成。
- 同一个总控如果也直接制作，算占1个制作名额；已打开但无任务的旧对话不算活跃，不为每个新单元再开一窗。
- 同一条真实动作续接链归同一制作对话依次处理；不同线共享阶段图仍可并行。一条线包含几个视频，不等于要开几个对话。
- 生成中或结果待用户取用/处理都占本批名额。默认每个制作对话维持1个正在生成或待处理的任务；可提前给本批需要的后续提示词，不以预写草稿为由继续堆付费生成。
- 一个任务取用、取消或明确暂停后，释放名额给下一项就绪任务。等尾帧的分支可明确暂停，安排别的就绪线；先保留未决项，不能把暂停当完成。无需等全部对话结束才补位。
- 若用户忙于切换、回传积压、重复修共用图，先减少活跃任务；若等待仍多且用户操作轻松、无积压，先在默认上限内补足。扩大上限只按用户明确调整执行，不自动“越多越快”。

平台的生成请求数另算：一个对话双抽也会消耗两个请求，不能用对话数代替平台容量。所有任务都缺同一张图时，先做那张共用图，不开三个对话分别修。

暂停任务不释放尚未结束的实际生成请求额度；不能把待用户处理的结果批量标“暂停”来绕过积压上限。容量调整应以实际排队、用户处理负担为依据。

## 四种依赖

| 类型 | 含义 | 调度 |
|---|---|---|
| D0 独立 | 不依赖前段动作或状态 | 自身输入齐备后，按容量调度 |
| D1 共享资产 | 复用同一人物、场景或道具真源 | 素材版本齐备后可并行 |
| D2 共享状态 | 同一完成/施工布局，不接上一秒动作姿势 | 可并行准备；必需参考卡与设置齐备即可生成，当前动作由正文指定，不等上游视频 |
| D3 尾帧依赖 | 必须承接上游实际动作姿势，无法用独立起点和允许的切镜替代 | 等前段可用截帧；只阻塞本分支的实际提交 |

硬切可以连接 D0/D1/D2，但仍要保持基本人物身份、空间和状态可理解。

分类前先检查合并：本可一条完成的“搬入→放下”，不要拆成两个 D3 再谈并行。施工顺序不等于生成顺序；“植物已摆好再摆椅子”可共享约定的植物布局，不必共享人物上一秒的手势。布局还未定的 D2 只等布局或状态图，不能假称立即可生成，也不要升级成等待整条上游视频。

本用户已明确采用选段硬切；D3 只用于具体需要无缝动作衔接的段落。复用某条视频的截帧不自动等于 D3：图片已存在且适用时，它就是当前可用输入。生成图的起点与最后进入成片的切入点分开记录即可，无需额外交接表。

这些标签是主要依赖的简称，不能取代真实输入清单。一个任务可能同时要人物图、阶段图和截帧，所有必需输入齐备才可提交；“D0/D2”不代表忽略缺图。图的父子依赖、视频的动作依赖和资源排队分开写。出现 A等B、B又等A时查清误标或缺少的共同状态，不凭空删依赖。

## 最小共享看板

项目已有 `当前进度.md` 或交接文件时，将其升级为 [唯一生产台账](production-ledger.md)，先展示关系图。下面表只是同一台账的进度视图，不复制维护；已经有等义字段就复用：

| 单元/原分镜 | 任务 | 依赖/具体缺口 | 阶段及共享素材版本 | 负责对话 | 状态 | 结果/下一步 |
|---|---|---|---|---|---|---|
| U01 |  | D0/D1/D2/D3 | ASSET-xxx V01 | A | 可开始/生成中/待尾帧/可用/需修 |  |

素材登记只需写 ID、路径、用途、禁止用途和版本。图片修订不覆盖原文件，生成新版本；合格尾帧也登记为新素材 ID。

已有编号、文件名和版本可直接沿用，不为登记另起编码体系。共享布局只锁定影响衔接的物件、数量和相对位置；非观看重点的背景细节不要求每段全部清楚可见。下游已经依此开工时，不随意改布局；确有必要的变更只通知受影响分支。

共用进度和有效版本只由总控更新；制作对话在各自任务输出位置保存图/视频及必要的提示词，短结果回给总控即可。状态至少区分缺输入、就绪排队、已分配/生成中、待用户处理、可用、需修、暂停；采用已有等义状态，不要求重建表。待用户处理不等于可用；用户按约定投放到可用目录即记录“用户已接受”，不追加AI审核。候选结果不自动接受，未看过不能写“AI已审核”。有效版本与投放约定按台账规范执行。

## 生产对话短任务包

正式跨对话使用 [项目快照](../templates/project-snapshot.md) + [单元卡](../templates/production-unit-card.md)，两份一起给；下列仅是简写，不与单元卡重复维护。卡带台账来源修订和输入版本；执行对话开始/恢复/提交前只重读相关记录，避免陈旧快照继续生成。总控发送：

```text
你负责：U__（对应原分镜__），本批任务__。
本段要看见：__；剪辑取用/硬时间__。
所属阶段：__；可用素材的绝对路径与指定版本：__。
要保留/尚不能出现：__；可自行调整：人物动作起点/机位等__。
依赖：D0/D1/D2/D3；具体等什么：__；工具模式/已核对设置或未知项：__。
你的输出位置和命名：__；不要改共用图和共用进度。
请回传：当前提示词、结果路径、使用版本、可用范围、下一步。
不要重新规划全片，不覆盖共享素材，不写长审核报告。
```

生产对话回传：

```text
U__｜素材版本：｜生成结果：｜可用范围：｜具体问题（如有）：｜下一步：
```

## 调度规则

1. 总控先定阶段依据、合并自然动作，再标依赖；为容量内的就绪任务指定负责人。超出容量的留队列，未定关键共享布局只停使用它的任务。
2. D3 只等待自己的上游实际输入；提示词和固定设置能提前准备就先准备，不让整条视频停摆。
3. 生产对话可同时准备独立制卡与视频正文；已有卡直接写视频，不为并行额外造图。普通参考中的完成样式可只借材料/目标，正文明确当前未完成部分；不把未来状态当默认开头。
4. 一个单元失败，只回溯受影响的下游；无依赖单元继续。
5. 同一素材有多个版本时，总控指定当前有效版本；制作对话不自行选最新文件。共享变更按阶段规划处理，本段姿势改图保存到本段，不升级为所有人的新依据。
6. 先并行做出可剪素材，再看粗剪是否需要局部修复。
7. 由负责制作的对话给齐本批任务的文件名、上传位置、已核对时长、可复制生图/视频正文和取用要求；总控有现成正文就直接复用，不两边各重写一份。缺图可先给正文，注明图可用后再提交。多余就绪任务只排队，不要求用户同时操作所有任务。
8. 生产等待时在容量内给一个真正可推进的任务；确实没有就如实说等什么，不用重复总结或重审填时间。跨对话准备短任务包不等于已派发；不能共享文件的环境随任务附必要素材和版本说明，不假定对话会自动看见彼此修改。创建对话、发消息、付费生成均按实际用户授权执行。

## 主要风险及最小防护

- 版本漂移：素材 ID + V01/V02，禁止覆盖；快照用 R 号，单元卡用 v 号。
- 转述偏差：人物、空间、风格用快照共享块原文拼接，不让各对话自己复述。
- 状态泄漏：任务包列出不可带入的未来状态。
- 隐形依赖：只写必须等哪一项，不笼统写“等前面”。
- 总控堵塞：总控只维护表和派发，不替每个对话重写长提示词。
- 回传混乱：结果带单元编号和素材版本。
- 错误尾帧传播：截帧要能支持下一段的起点，不把可见硬伤传下去。续接动作可使用运动中的清楚姿态，并非一律要人物松手静止；只有动作完成本身是目标时才要求完成态。

对话太多而难以管理时，减少并行数量；并行不是越多越好。判断是否成功看等待期间是否有其他单元推进、版本是否一致、粗剪是否成立，不看对话数或文件数。

跨对话项目以 [生产台账](production-ledger.md) 的单元卡为执行依据。变更只刷新受影响的卡与节点；文件不会自动广播给各对话。用户接受局部视频不自动让其中随机布局改成全片真源。提示词由一个位置维护，单元卡已有正文就不在总控重写。
