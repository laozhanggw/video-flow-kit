# 交给自动生产程序：适配现有导入程序的输入格式（2026-10-06 定稿，硬规则）

这一步只做一件事：把已经写好的图片、视频生成任务，整理成用户现有 Python 导入程序（VisualGPT 程序 `E:\YouTube智线\阳台视频项目\visualgpt-channel-poc` 的 `双击_导入项目.cmd` → `python\import_project.py`）能读取的生产项目。

这是“适配输入格式”，不是改程序，也不是重新设计内容。已确认的剧情、动作、参数、参考图一律不动；格式和原内容冲突时，列出冲突，未解决前保持草稿。

最终目标：

1. 所有要生成的图片和视频，都有独立、完整、可追溯的生产任务。
2. 导入程序能准确提取提示词、参考图路径、上传顺序、生成参数和输出文件名。
3. 导入后的 Excel 与源任务逐项一致：不漏任务，不猜路径，不擅自改参数。
4. 图片生成后能被下游视频任务按准确路径引用。
5. 所有结果按固定文件名归档到项目 `生成` 文件夹。

## 1. 固定文件结构

```
项目文件夹/
├─ 共用卡制卡词.md        ← 所有图片任务
├─ 单元/
│  ├─ U01.md               ← 每条视频一个文件
│  ├─ U02.md
│  └─ ……
├─ 说明/                   ← 创作分析、讨论、历史、待确认（程序不读）
│  ├─ 共用卡说明.md
│  └─ U01_说明.md ……
├─ 导入核对清单.md         ← 每次交付必交
├─ 原始参考图片（直接放项目根目录，如 人物参考.png）
└─ 生成/                   ← 程序输出；生成\_待审 是待审区
```

快照、台账可以照旧放项目根目录，它们不是程序读取文件。

要求：

- 所有 Markdown 用 UTF-8。
- 图片任务全部写进 `共用卡制卡词.md`。
- 视频每条任务一个文件，放进 `单元` 文件夹。文件名固定为 `U01.md`、`U02.md`……，不加中文说明，不加版本号。
- `单元` 文件夹里只放视频任务卡。程序会把这里每个 `.md` 都当成一条视频，说明文件放进 `说明` 文件夹。
- 不自己制作、覆盖或删除 Excel；不改 Python 程序；不删台账；不靠换项目名绕过防重复提交。
- 创作分析、讨论、历史记录、版本记录、待确认事项一律放进 `说明\` 里的文件，不混进程序读取的字段和代码块。

## 2. 图片任务格式（共用卡制卡词.md）

每张图片严格用下面的结构：

````
## RC01｜简短中文名称

生产状态：定稿
父图：项目文件夹\原始参考图片.png
输出：生成\RC01_简短中文名称_v01.png｜GPT Image 2.5 Flare｜3:2｜2K｜Medium

```text
这里填写完整、可直接提交给网站的图片提示词正文。
```
````

规则：

1. 标题固定为 `## RC编号｜中文名称`，例如 `## RC01｜人物身份`。
2. 每个图片章节只有一个最终的 ```text 代码块。
3. 提示词前不插入其他二级标题，也不放其他 text 代码块。
4. `父图：` 和 `输出：` 必须写，不能改叫“参考素材”“保存位置”等。
5. 纯文字生图明确写 `父图：无`。
6. 多张父图用全角 `｜` 分隔，从左到右就是实际上传顺序：
   `父图：项目文件夹\人物参考.png｜项目文件夹\生成\RC02_空间参考_v01.png`
7. 父图字段只写路径，不夹职责说明。参考图职责写进最终提示词（“第1张图负责……”），或写进 `说明\共用卡说明.md`。
8. 输出字段顺序固定：`生成\文件名.png｜模型｜比例｜清晰度｜画质档`。
9. 每个参数都显式填写，不依赖程序默认值。
10. 示例里的参数只是格式示例。实际值用已确认、网站支持的参数，不擅自替换。
11. 图片文件名固定为 `RC编号_简短中文名称_v版本.png`。
12. 图片任务的版本就是输出文件名里的 `v01`、`v02`。
13. 图片参考图最多 4 张，而且不超过所选模型实际支持的数量（见 SKILL.md 渠道参数表）。

`共用卡制卡词.md` 里只放 RC 章节。文件开头可以有一行 `# 项目名｜共用卡制卡词`，但不要写别的 `## ` 二级标题（程序把每个以字母开头的 `## ` 都当成一张图），验收清单和说明写进 `说明\共用卡说明.md`。

## 3. 视频任务格式（单元\U01.md）

每个视频文件严格用下面的结构，从第 1 行开始：

````
# U01｜简短中文名称

> 本卡版本：v01
> 生产状态：定稿
> 生成：6 秒｜Seedance 2.0 Mini｜9:16｜480P｜声音开
> 上传顺序：1 人物身份 = 项目文件夹\人物参考.png｜2 空间参考 = 项目文件夹\生成\RC02_空间参考_v01.png
> 输出文件名：U01_v01.mp4

## 拼好的完整正文

```text
这里填写完整、可直接提交给网站的视频提示词正文。
明确第1张图、第2张图各自的职责，并写齐动作、时间安排、画面和声音要求。
```
````

规则：

1. 上面的引用字段全部放在文件前 15 行内，直接沿用示例布局。
2. 单元编号由文件名决定：`U01.md` 对应 U01，标题也写 U01，不能文件名 U01、正文写 U02。
3. `本卡版本` `生产状态` `生成` `上传顺序` `输出文件名` 五项都显式填写。
4. 最终正文标题准确写为 `## 拼好的完整正文`，不改成“最终提示词”“视频Prompt”“完整提示词”。
5. 该标题后紧接唯一的最终 ```text 代码块。
6. 上传顺序写在同一个实际文本行里，用全角 `｜` 分隔。
7. 每项格式固定为 `数字 空格 素材名称 = 图片路径`。
8. 编号从 1 开始连续排列，文本顺序与编号一致。
9. 不写“上传人物图和场景图”代替具体路径。
10. 视频必须有参考图；数量和生成参数符合所选网站模型的实际能力（见 SKILL.md 渠道参数表）。
11. `生成` 字段顺序固定：`时长 秒｜模型｜比例｜清晰度｜声音开` 或 `声音关`。
12. 时间轴不超出生成时长，不能用一个短时长字段包住超长正文。
13. 视频输出名固定为 `U编号_v版本.mp4`。
14. 文件版本、头部 `本卡版本`、输出文件名里的版本三者一致。

单元卡里除了标题、五行头部和这一节，不放别的内容。原单元卡里的“这条线一眼看懂、输入与缺口、专属部分、空间合同、版本记录、复制给新对话、回传”等全部移到 `说明\U01_说明.md`（模板见 [单元说明](../templates/production-unit-notes.md)）。

## 4. 路径与依赖

统一用两种写法：

- 已有原图：`项目文件夹\准确文件名.png`
- 上游生成图：`项目文件夹\生成\RC编号_准确名称_v01.png`

要求：

- `项目文件夹` 保留为字面前缀，导入程序会替换成用户选的项目实际路径。
- 写准确扩展名和完整文件名。
- 不写“上一张图”“人物图”“同上”“待补图片”等模糊指代。
- 不引用 `生成\_待审` 里的图片作为正式生产参考。
- 已有原图必须真实存在。逐个打开或列目录核对；没有读取权限就在核对清单写“待核对存在性”，不能说已检查。
- 还没生成的图可以用准确的计划路径引用，但必须有对应的上游 RC 图片任务。
- 上游图片的输出名与下游引用路径完全一致（RC 的 `输出：生成\X.png` ⇔ 下游 `项目文件夹\生成\X.png`）。
- 依赖不能成环。
- 不擅自把路径猜成其他相似文件。找不到就列为缺口。

## 5. 提示词完整性

最终代码块里是完整生成正文：

- 不写“同上”“沿用前文”“参考之前版本”代替正文；共享块按快照原文照贴。
- 不留省略号、待填字段、`{{占位符}}`。
- 不把讨论、审批说明、给用户的操作建议放进最终提示词。
- 不把解释性文字当作网站生成正文。
- 不为适配格式而擅自改用户已确认的剧情、动作、参数或参考图。
- 原内容和时长、上传顺序等冲突时，明确列出冲突；未解决前保持草稿。

## 6. 生产状态

每条任务明确写两种之一：`生产状态：定稿` 或 `生产状态：草稿`。

1. 用户已明确批准纳入本次生产、且没有未决内容问题的任务，写定稿。
2. 有未解决问题或待用户确认的任务，写草稿，并在核对清单和说明文件里列出具体缺口。
3. 不因为文字写完就擅自标定稿。
4. 用户已批准整套生产且任务完整时，不沿用过时的草稿状态，导致导入漏项。
5. 上游图片还没生成、但依赖明确且有对应任务时，不单凭这一点把下游视频列为草稿（程序会自动等上游图）。
6. 不省略状态，不用“已写齐”“待处理”等自由文字代替。
7. 同一任务不能同时写 `生产状态：定稿` 和“当前不可提交”“暂缓”（程序见到这些字会当草稿跳过）。
8. 历史限制已经解除时，在说明文件里标明属于历史说明，不在任务卡里留下互相矛盾的当前指令。
9. 定稿表示可纳入生产，不表示已生成、已审核画面或已下载。

## 7. 编号与版本

- 图片用 RC01、RC02……；视频用 U01、U02……。
- 编号唯一，不重复，不仅靠大小写区分。
- 输出文件名不重复，不含 Windows 非法字符 `\ / : * ? " < > |`。
- 保留用户已有编号，不为排版整齐重编号。
- 已冻结或已提交的任务不能直接覆盖（程序对已提交行一个字都不改）。
- 要改已提交内容：写明新版本号和修改原因，按用户授权处理；单元卡 `本卡版本`、输出文件名同步升 v02，图片输出名 `_v01` 改 `_v02`，下游上传顺序里的路径同步改。不偷偷换版本重复付费。
- 还没提交过的任务，直接改 md 再导入，程序用新原文覆盖。

## 8. 导入程序的解析细节（照现有 import_project.py，写的时候避开）

- `共用卡制卡词.md` 里每个以字母开头的 `## ` 标题都会被当成一张图片；`父图：` `输出：` `生产状态：` 取章节内第一次出现的那一行，所以这三行放在标题和代码块之间，正文里不要以这些词开行。
- 代码块必须在下一个 `## ` 标题之前出现，否则这一节缺提示词被跳过。
- 父图和输出参数里的括号内容会被程序删掉，所以字段里不写括号说明。
- 视频 `生成：` 各段的识别方式：`数字:数字` = 比例，`数字P` = 清晰度，`声音…` = 声音，含英文字母的其他段 = 模型。模型名不含英文字母时程序会退回默认模型，写之前确认。
- 上传顺序每项按 `数字 空格 名称 = 路径` 解析：素材名称里不能有 `=`，路径里不能有 `｜` 或 `|`。
- “拼好的完整正文”这几个字在单元卡里只出现在那一个标题上。
- `生产状态` 或头部里出现“草稿”“不可提交”“暂缓”都会被跳过。

## 9. 导入核对清单.md（每次必交）

放在项目根目录，模板见 [导入核对清单](../templates/import-checklist.md)。每条任务一行：

`任务编号｜类型｜版本｜生产状态｜参考图上传顺序及准确路径｜已有素材或上游依赖｜生成参数｜输出文件名｜未决问题`

结尾分别统计：定稿图片、定稿视频、草稿图片、草稿视频各多少条；预计本次源文件可导入任务多少条；草稿或不导入任务逐条写编号和原因。

已有 Excel 可能保留历史行，源任务数量不一定等于 Excel 总行数。核对时比较当前任务编号，不只看总行数。

## 10. 交付前自检（逐项确认，写进核对清单末尾）

1. 文件名和目录正确。
2. 所有当前任务都出现在标准生产文件或明确的草稿清单中。
3. 所有机器字段用固定名称，没有自行换标题。
4. 每条任务只有一个完整的最终提示词代码块。
5. 参数全部显式填写。
6. 输入路径准确，上传顺序连续。
7. 上游输出与下游引用完全一致，依赖无环。
8. 任务编号、版本、输出名一致且无冲突。
9. 状态与当前授权及内容完整性一致。
10. 预计导入数量能由逐条清单核算。

能运行导入器时，只做隔离的离线解析验证：只调用 `Project(项目文件夹).rows()`，看读到的任务编号和 `skipped` 跳过原因，不调用 `run()` / `merge()`，不写表、不写指针、不启动付费生产、不改正式台账：

```
cd /d E:\YouTube智线\阳台视频项目\visualgpt-channel-poc\python
python -c "import import_project as ip; p=ip.Project(r'项目实际路径'); rows=p.rows(); [print(r['任务编号'], r['输出文件名'], r['参考图']) for r in rows]; [print('跳过', s) for s in p.skipped]"
```

不能运行时，核对清单里明确写“已按格式逐项检查，未实际运行导入器验证”，不能说已通过程序验收。

## 11. 交付与告诉用户

直接交付标准文件和核对清单，不只给框架，不让用户自己整理。最后三行告诉用户：哪些任务定稿可导入（写明编号@版本）、哪些是草稿及缺什么、下一步“双击 `双击_导入项目.cmd` 选本项目文件夹，没有 !! 就双击 `双击_正式生产.cmd`”。

新项目的设置页由导入程序按用户定的默认值填好（2026-09-29：自动付费=是、技术放行=是、图片4/视频400/每日2000、并发1、巡检60秒）；老表的设置只由用户改。依赖不写依赖列，靠参考图路径自动识别。
