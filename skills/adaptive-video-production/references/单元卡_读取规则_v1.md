# 单元卡读取规则 v1（2026-11-01）

**用途**：写卡 AI 的唯一依据。程序按本文件逐字读取 `单元\U0N.md`；不按这里写的，程序多半不报错，只会「读不到」或「少跑几条」。
**配套**：具体怎么写（图片提示词五段、视频提示词十块、完整示例）见 [生产单元_写卡格式_v1](生产单元_写卡格式_v1.md)；只读校验 `python "{{ROOT}}/tools/Pipeline.py" 查 单元 --版本 "<本版本目录>"`（卡格式已并入总闸门）。
**对应程序**：`E:\YouTube智线\阳台视频项目\visualgpt-channel-poc - 副本\python\import_project.py`
**事故来源**：2026-11-01 B0018 `V02_front_steps`，三条单元卡把「（已有）」写进路径，三条视频被判「素材没到位」静默跳过，界面仍显示「完成」。

---

## 1. 文件层

- 固定位置：`项目文件夹\单元\U01.md`、`U02.md`…。**文件名（去掉 .md）就是任务编号**。
- 编号只允许字母、数字、下划线、连字符；不能有中文、空格、`.`、`:`、`|`。
- 一个 `.md` = 一条视频任务。
- **`单元\` 里只放 U*.md**。说明书、笔记、模板放 `说明\`，否则每次导入都会多一条「不导入」提示。
- 编码 UTF-8。

## 2. 头部：文件前 15 行里、以 `>` 开头的行

程序**只看前 15 行**里的 `>` 行。五项缺任何一项 → 整张卡**不导入**。

| 字段 | 必须写成 | 说明 |
|---|---|---|
| 本卡版本 | `> 本卡版本：v01` | 只认 `v` + 数字；写成「v01 已写」「第1版」→ 不导入 |
| 生产状态 | `> 生产状态：定稿` | 含「草稿／暂缓／不可提交」→ 记草稿；写「暂停」无效，按定稿处理 |
| 生成 | `> 生成：15 秒｜Seedance 2.0 Mini｜9:16｜480P｜声音开` | 见第 3 节 |
| 上传顺序 | `> 上传顺序：1 名称 = 路径｜2 名称 = 路径` | 见第 4 节 |
| 输出文件名 | `> 输出文件名：U02_v01.mp4` | 不写就默认 `U02_v01.mp4`，容易和别的单元撞名 |

**字段名只有上面这五个字。** `生成参数：`、`参考图：`、`上传参考图：`、`时长：` 程序都不认。

## 3. 生成行怎么拆

1. `> 生成：` 后面**第一个字段必须是「数字 秒」**。
   - ✅ `15 秒`、`15秒`、`15.4 秒`（小数向上取整，记 16 秒并在备注写明）
   - ❌ `约 15 秒`、`十五秒`、`15`（没有「秒」字）→ 整张卡不导入
2. 后面用全角 `｜` 分隔（半角 `|` 也认），程序**按长相认、不按位置**：

| 长相 | 落到哪 |
|---|---|
| `9:16`、`16:9` | 比例 |
| `480P`、`720P`（必须带 P） | 清晰度 |
| `声音开` / `声音关` / `声音自动` | 声音 |
| 任何含英文字母的字段 | 模型（出现多次时最后一个生效） |

3. 不带英文字母的说明文字（如「按上次参数」）不会进模型列，会被丢掉但**不报错**——别指望它生效。
4. 默认值：`Seedance 2.0 Mini｜9:16｜480P｜声音开`。

## 4. 上传顺序（最容易出事的一行）

格式：`> 上传顺序：1 名称 = 路径｜2 名称 = 路径｜…`

**硬规则**

1. **整行必须是一行**，中间不能换行。
2. 每一段必须能拆成 `数字 空格 名称 = 路径`。缺 `=`、开头缺数字、名称里有 `=`、路径里有 `｜` 或 `|` → **整批导入直接中断**，报「上传顺序看不懂」。
3. `=` **左边**是素材名称，随便写注解：`1 主角身份（工人·已有）` ✅
4. `=` **右边**只放路径，**到扩展名结束**，必须是 `.png` / `.jpg` / `.jpeg` / `.webp`：
   - ✅ `项目文件夹\生成\RC01_主角四视图_v01.png`
   - ❌ `项目文件夹\生成\RC01_主角四视图_v01.png（已有）` ← 2026-11-01 三条视频就是这么被跳过的
   - ❌ `项目文件夹\生成\缺`（占位符不是路径）
5. 路径只有两种写法，`项目文件夹` 是字面前缀，程序会替换成真实路径：
   - 已有原图：`项目文件夹\准确文件名.png`
   - 上游生成图：`项目文件夹\生成\RC编号_准确名称_v01.png`
   - 下游这条路径必须和上游卡的 `输出：生成\X.png` **一个字不差**。
6. 张数：网站在线生成一次最多 **4 张**，按 ≤4 写。不许用「同上」「人物图」「待补」代替路径。
7. 顺序 = 网页上的上传顺序 = 提示词里「第 1 张图…／第 2 张图…」的编号，**必须一一对应**（提示词里点到「图4」而只传 3 张，审计会拦）。

> 程序现在会兜底：路径末尾的括号注解会自动去掉并在导入日志提醒。**但不要依赖兜底**，注解永远写在 `=` 左边。

## 5. 提示词

- 必须有 `## 拼好的完整正文`。可接受的别名：完整正文／最终提示词／最终正文／提示词正文／提交用提示词／可直接提交的正文／视频提示词。
- 该标题之后**第一个** ` ``` ` 或 ` ```text ` 代码块就是提示词，**逐字入库，不做任何清洗**。
- 代码块里不能出现 `{{ }}`（占位符）→ 有就不导入。
- 同一节不要放第二个代码块；` ```js ` ` ```json ` 这类不会被当提示词。
- 程序读到下一个 `## ` 标题就截止，别把正文放到下一个二级标题之后。

## 6. 判「不导入」的六种情况（日志里能搜到）

1. 缺 `拼好的完整正文` 代码块
2. 缺 `> 生成：`
3. 缺 `> 上传顺序：`
4. 提示词里有 `{{占位}}`
5. `生成：` 开头不是「数字 秒」
6. `本卡版本` 不是 `v01` 这种写法

## 7. 会进表、但生产时一直「等素材」的情况（不报错，最难发现）

- 参考图指向的文件**不存在**，且不是本项目任何任务的输出名 → 判「等派生输入」，这条视频**静默跳过**，其余照跑。
- 参考图指向一个**已作废**任务的输出 → 整批报错（这个会报，能看见）。
- 参考图不是图片扩展名 → 审计报 `REFERENCE_NOT_IMAGE`，只是提醒，**不拦**。

## 8. 图片卡（共用卡制卡词.md）的差别

- 每张卡是 `## RC01｜名称` 或 `### RC01 · 名称`；段内写 `父图：` `输出：`。
- `父图：无` = 这张图不传参考图（纯文字生图）。
- `输出：生成\X.png｜模型｜3:2｜2K｜Medium` —— 路径在前，后面按长相认（比例 `数字:数字`、清晰度 `数字K`、画质档 `Low/Medium/High`）。
- 图片卡的父图栏会把括号注解**整段清掉**，所以 `场景(2).png` 这种名字反而有风险，别用。
- 已有成品卡（不生成的）**不要写 ` ```text ` 提示词块**，程序会跳过它——这正是「已有资产」想要的（不生成、不花钱），代价是每次导入多一条「缺提示词，不导入」的提示。想彻底安静，就把这类卡从制卡词文件里拿掉，只在 `说明\` 里记一笔。

## 9. 重写单元卡时的边界（务必遵守）

- **只改前 7 行**：标题 + 五个头部字段 + 空行。提示词正文、覆盖范围、版本记录**一律原样保留**——那些词已经验收过，动了就是重做。
- 不改：单元编号、版本号、时长、输出文件名、参考图张数与顺序。
- 时长是生成参数，改了就是另一条任务，成本跟着变。
- 改完逐条自检：① 五个字段齐全且都在前 15 行 ②上传顺序是一行 ③每段有 `=` ④路径以 `.png` 结尾 ⑤编号 1..n 连续。
