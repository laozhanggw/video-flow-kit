# 参考卡、首帧与续接：按实际输入职责选择

本用户生活类改造短视频、工具支持普通多参考时，先用少量可复用多视图参考卡直接生视频。方法由2026-09-14用户实战确认总体显著提速；完整路径、原话与失败见 [鸽子实战](../examples/pigeon-multiview.md)。不保证所有镜头和模型均无需局部补图。

## 图片各负责什么

| 类型 | 职责 | 使用边界 |
|---|---|---|
| 人物/道具身份卡 | 同一对象的必要角度、外观、服装或材料 | 够用即复用；已知背面/手部等缺口可提前补，不必先失败 |
| 共同空间卡 | 建筑尺度、门、栏杆、动线及共同布局 | 可为同一空间多机位；是否用完成态作母卡由已有素材决定 |
| 阶段多视图参考卡 | 同一施工阶段的整体、反向视角和关键细节 | 多段共用；阶段数不决定卡数，卡数不决定单元数 |
| 局部构图图 | 特定相机位置、物理边界、姿态或接触 | 只补明确缺口；可作普通参考，未必占首帧位 |
| 单幅首帧图 | 锁定视频开始的一幅画面 | 模式需要或具体控制有价值才用；可用已有图/截帧，不每组新生 |
| 续接截帧 | 接同一实际动作的姿态、方向和轴线 | 确需无缝动作才等对应可用帧，可为中间帧 |

参考卡是图片，一张可分格呈现同一对象/阶段多个视图；生产卡是操作文字。单幅9:16状态照不是多视图卡。卡画幅、视图数、数量按可读性、上传限制和所需阶段选择，不固定3/5张、四格、2:3或6:19。

## 默认决策顺序

1. 从 [阶段规划](state-planning.md) 取得终局、必要阶段和有效身份/空间依据；先明确借图职责，不从上一条随机结果决定全片布局。
2. 普通参考模式：选本组必需身份和空间/阶段卡，在视频正文明确当前状态、动作和机位。够用就直接视频，不新增每组首帧节点。
3. 阶段确缺共同依据时制卡：同一对象、同一阶段，多角度/细节相容。每张待制卡登记来源→生图词→输出名和服务组。建筑依据可用后独立阶段卡可并行，不把施工先后当图片依赖。
4. 卡上画了完成样式，视频也可以从未完成开始：卡只借安装位置和材料，正文写明当前进度（例如网还卷着没展开，或者只剩一处绑带待收紧）。如果视频反复直接跳到完成态，就去掉这张冲突图或限定它的职责，必要时补一张局部几何图。
5. 工具仅支持首帧，或已知关键构图需要锁定时选择单幅起点；不能把分格卡直接塞首帧并期待自动还原正常全屏。选合适单视图、裁切或局部补图转换，并标真实输入位置。
6. 同一动作必须无缝延续才取实际衔接帧。普通硬切素材不等上一条，也不先要求剪完上一条才能做下一条。

模式未知先读已有记录，缺参数集中问一次；规划和正文继续，实际提交保留具体缺口。不能凭“第一张图”臆测首帧权重、API槽位或图数上限。

## 上传前检查输入是否真的能支持动作

逐张看实际画面，而不只读文件名和标签。核对当前状态、目标状态、人物服装、床/窗/外墙几何、材料来处及相机角度。如果目标卡把本段尚未出现的顶部、玻璃、软装等画得很显眼，文字“只借局部、忽略其余”不保证模型听从：先减少冲突图片或换合适视图/裁切；确实影响生成时才补局部参考。不能用互相矛盾的图再叠几十条“禁止”冒充解决。参考图已是规整洞口，就不要凭同一张图要求它从粗糙修齐。

**参考图真实感先于视频形容词。**检视房屋尺度、材质、可用动线、物件用途、自然/现场光、是否过度对称、过度洁净或像广告效果图。保留必要的生活使用状态和施工痕迹，不随意加垃圾、脏污、噪点或虚构损坏。多视图中几何/同阶段关系互相冲突，先修输入；仅说“手机随手拍”通常无法把样板间画面改成真实生活。细节按画面景别选择，不把脸部毛孔等远景看不见的元素当成必填项。

## 当前阶段与目标图

输入只用本组必要且工具支持的卡，不传全套前中后阶段。分别写清身份、建筑、材料、当前状态、目标样式：

- 施工过程段：当前阶段卡加上人物卡就够了。目标阶段卡最多作为可选输入，开头不能出现已完成的样子。正文能说清目标时，就不要传这张可选卡。
- 完成空间卡用于早期制卡：只借建筑/尺寸，明确当前尚无哪些新设施；不强制每个项目先画完成态母卡再倒推。
- 同一卡不混相互冲突施工阶段；视频可按正文跨阶段或内部切镜，卡的视图不是视频时间线。

目标图片如果实际上传，就是材料输入，图表标“可选输入”；如果只读文字目标，不画成必需上传。已有卡不强迫每段先拍它的全景。

## 标签与画幅

卡面可在留白写简短中文卡名、稳定编号、分区标签，不遮挡人物、网边或固定点。标签帮助人工理解，不是API语法。错字可简化或后期标注，不为小字无限重抽。
视频正文要求正常满屏，不复制卡标题、边框、分区、文字或拼图。“成片不要分屏”不等于“参考卡禁止分格”。

## 局部几何失败与首帧例外

内外翻转是已知的高发错误。预防靠 SKILL.md 第 5 步的空间合同。已经翻转时，只给这一个单元补一张局部构图：相机和外部对象放在屏障外侧，屏障横在画面中间，人和室内锚点在屏障内侧。这张图按实际模式当普通参考或单幅首帧使用。共享卡和其他已可用的视频保留不动。补图是否有效，要看新生成的结果（实例见 [鸽子 T12](../examples/pigeon-multiview.md)）。

图可用不保证视频动作成立。前段视频能用而截帧不适合后段时，保留视频，选其他帧、独立构图或允许的切镜；不为续接方便重做上一条。画外/合理遮挡不等于道具丢失。
首尾帧模式仅当两端控制有价值且工具支持时使用；两端要允许动作发生，不能保证中间物理或终点精确实现，不一律要求人物停稳松手。

## 最小交付与历史来源

在同一生产卡写：真实路径/版本、每张职责和已核实输入位置、现在做什么、真正等什么、具体失败才补什么。缺图不假装存在，用户已接受不追加AI审核，不另开审批卡。
