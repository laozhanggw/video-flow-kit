# 文件驱动生产：用短上下文并行写词

本文件解决两个问题：长对话会遗忘设定，逐条串行写词太慢。核心做法有三条：

1. 信息存在文件里，不靠对话记忆。
2. 每条提示词都在一个全新的短上下文里写。
3. 反馈和修改写回文件，不堆在对话里。

单元数达到 4 个及以上，或者用户要求并行时，默认采用本方式。3 个及以下可以由总控直接写，但仍然要先写快照。

## 1. 三类文件

项目目录里固定放这三类文件。目录位置沿用项目已有位置。

| 文件 | 内容 | 谁能改 |
|---|---|---|
| `00_快照_R01.md` | 终局、阶段路线、单元表、图片职责表、共享块、已知坑 | 只有总控；一改就升 R 号，另存新文件 |
| `台账.md` | 进度、实际文件路径、版本、接受状态、问题清单 | 只有总控 |
| `单元/U01.md` | 程序读取的任务卡：标题、五行头部、`## 拼好的完整正文` 下唯一 text 块 | 负责这个单元的子任务；修复时新增版本 |
| `说明/U01_说明.md` | 本单元的专属内容、空间合同、输入表、待总控、版本记录 | 同上 |

模板见 [快照模板](../templates/project-snapshot.md)、[单元卡](../templates/production-unit-card.md)、[单元说明](../templates/production-unit-notes.md)；任务卡格式以 [交给自动生产程序](auto-production-table.md) 为准。快照是“要做成什么”的冻结版，台账只记“做到哪了”，两边不重复写同一件事。

每做一个决定、每改一处、每接受一个版本，都立刻写进对应的文件。对话随时可以关掉：新对话读快照和台账，就能接着干。总控自己聊久了、开始遗忘时，也照这个办法重开。

## 2. 共享块：写一次，原文拼接

不同对话用自己的话复述同一件事，是理解偏差的主要来源。所以跨单元不变的内容写成固定文字块，存进快照，每条提示词都原文照贴，任何子任务都不改写。

| 块 | 内容 |
|---|---|
| `[画面规范]` | 画幅、正常满屏、不复制参考卡的标签和分格、无字幕 |
| `[人物-P01]`…… | 每个人物一块：身份、服装（按阶段分，写成不同版本） |
| `[空间]` | 空间锚点、室内外分界、不变的建筑关系 |
| `[风格光线]` | 真实感、光线、相机观感 |
| `[环境底声]` | 本项目的低音量空间底声 |

外观一律写“与第 X 张参考图一致”，再加共享块。不在专属段里重新描述外观，这样图和文字不会打架。

子任务只写本单元专属的内容：阶段起止状态、动作、接触和状态变化、镜头与机位、动作音效，以及本单元的空间合同（如果需要）。

拼接顺序固定，对应 SKILL 第 6 步的正文顺序：

```
[画面规范] → 参考图职责行（第X张=…）→ [人物-Pxx] → [空间] + 本单元空间合同
→ 专属：阶段/动作/接触/镜头 → [风格光线] → 专属：动作音效 + [环境底声] → 本单元负向约束
```

## 3. 参考图：提示词附验收清单

制卡提示词可以先写好，一次批量生成，不必等图出来再写视频词。每条制卡词后面附一份验收清单：

- 必须有：3–6 条，比如关键视图、关键状态、关键接触面。
- 不能有：2–4 条，比如阶段泄漏、多余道具、内外翻转。

用户对照清单人工审图。图过关，就把实际文件名和版本登记到台账。视频词本来就写“与第 X 张参考图一致”，不用改。

用户接受了一张有偏差的图时，把偏差写进台账，只改引用这张图、而且受影响的视频词。其他单元不动。

## 4. 子任务怎么派

每个子任务只拿到这些材料：

1. 快照当前 R 号的全文。
2. 负责的单元卡和对应的单元说明。
3. 本文件和 SKILL 第 5、6 步。
4. 一句任务说明：写哪几个单元，交回哪个文件。

不给整段历史对话，也不给其他单元的正文。子任务写完单元卡就结束，不自己去改快照。发现快照有问题，就在单元说明的“待总控”一栏里写明，交回总控裁定。

分组规则：

- 按阶段分组。相邻的、有衔接的单元放进同一个子任务，保证交接状态一致。
- 每个子任务 2–4 个单元。同时最多开 4 个子任务。
- 写词子任务不占生成名额。渠道的图片和时长上限只约束最终提示词本身。

## 5. 按阶段批处理

| 轮次 | 做什么 | 产出 |
|---|---|---|
| A 定稿 | 总控写快照：终局、单元表、图片职责、共享块 | 快照 R01 |
| B 制卡 | 批量写全部制卡词和验收清单 → 用户一次生成、一次审完 | 台账登记图片 |
| C 写词 | 子任务并行写单元卡 → 总控拼接 | 全部单元卡 v01 |
| D 检查 | 开新上下文，对照第 6 节清单检查全部正文 | 通过/问题清单 |
| E 生成 | 用户一次生成全部视频，一次汇总问题 | 台账问题清单 |
| F 修复 | 按问题清单再派子任务，只改有问题的单元 | v02… |

不要生成一条、修一条、再写下一条。每轮做完再进入下一轮，节奏由轮次控制，不靠逐条对话。

## 6. 提交前检查（新上下文）

检查不能由写词的对话自己做，它会带着自己的理解去看。要另开一个只读快照、台账和单元卡的上下文，逐条核对：

| 项 | 通过标准 |
|---|---|
| 图 ID 与版本 | 正文里“第X张”与台账登记的实际文件和版本一致；张数不超上限 |
| 共享块 | 与快照当前 R 号逐字相同，没有被改写或删减 |
| 阶段泄漏 | 起点没有后续阶段的物件或状态；终点没有越过本单元的终局 |
| 空间合同 | 需要合同的单元四行齐全；和相邻单元的锚点不冲突 |
| 衔接 | 上一单元的终点状态等于本单元的起点状态 |
| 时长与密度 | 动作量装得进设定秒数；台词按字数/秒核过 |
| 语言 | 正文是简体中文；每句台词与小分镜原文逐字一致，语言没被翻译 |
| 负向约束 | 覆盖快照“已知坑”里和本单元相关的条目 |
| 导入格式 | 按 [交给自动生产程序](auto-production-table.md) 第 10 节十项自检全部通过，`导入核对清单.md` 已写 |

输出只写“通过”，或者列出“单元—问题—建议改法”。总控按清单决定改不改。

## 7. 反馈写回与已知坑

用户反馈的问题，总控先分成两类：

- 单元问题：只影响这个单元。写进该单元卡的版本记录，升 v 号，派修复子任务。
- 通用问题：换个单元也会出现，比如某类动作总是穿模，或某个词总让模型加字幕。写进快照的“已知坑”，升 R 号。之后所有新词和修复都要带上对应的约束。

修复子任务只拿快照、这张单元卡和问题描述。它只改专属部分，不改共享块。要改共享块，说明是通用问题，由总控升快照。

旧版本不删除，在单元说明的版本记录里保留一行：版本、改了什么、为什么、由谁改（修复子任务 / 总控直接改）。总控直接改的，也要写这一行，不然事后查不到。

偶发穿帮（手穿玻璃、穿模、道具瞬移）先按 [抽卡与止损](sampling-and-stop-rules.md) 开头那段处理：剪掉或重抽，不算单元问题，不派修复。

## 8. 边界

- 这套结构能消除遗忘和转述偏差，但不能消除模型的随机性。同一条词生成出不同结果是正常的，先重抽 1–2 次，再判断是不是提示词的问题。
- 快照写错了，所有单元都会一起错。所以 A 轮定稿后，先请用户确认终局和单元表，再进入 B 轮。
- 子任务之间不互相通信，所有协调都经过文件和总控。

## 9. 谁主动、用户找谁

### 用户只跟总控说话

用户开的第一个对话就是总控，自始至终只有它面对用户。子任务是总控派出去的工人：它写完单元卡就交回，不直接找用户，用户也不需要去找它。

- 看图、看视频后发现的问题，一律发给总控。总控分类、写回文件、派修复子任务，修好后把新版本交给用户。
- 子任务出错（写偏、漏共享块、格式乱），也由总控在检查时发现和处理，不需要用户介入。
- 只有一种例外：因为环境不能自动开子任务，由用户手动开了窗口（见下）。那个窗口只负责把卡写出来，写完就关掉。问题仍然回到总控说。

### 总控自己判断什么时候开子任务

用户不需要提醒。总控在这些时刻必须主动行动：

| 时刻 | 总控自己做 | 对用户说 |
|---|---|---|
| 第 2 步单元定完 | 数单元：≥4 个就走本文件，≤3 个自己写 | “共 N 个单元，按分组并行写 / 我直接写” |
| A 轮快照写完 | 停下等确认 | “请确认终局和单元表，确认后出制卡词” |
| B 轮用户审完图 | 登记台账，按第 4 节分组，自动开写词子任务 | “开始并行写 N 组，写完我统一检查” |
| C 轮子任务交回 | 自动开检查子任务 | 不打扰用户 |
| D 轮检查通过 | 整理成一份提交清单 | “可以一次性生成这 N 条了，生成完把问题一起告诉我” |
| E 轮用户报问题 | 分单元问题/通用问题，自动开修复子任务 | “X 条单元问题、Y 条通用问题，已在修” |

每轮结束时，总控都用三行告诉用户：刚做完什么、现在需要用户做什么、下一轮是什么。

### 不能自动开子任务时

先试着自己开子任务。开不了（环境不支持或额度满了），就让用户手动开，总控把要发的话一次给全：

```text
请新开 N 个对话，每个发下面对应的一段，写完回我一句“G1 写完了”即可：

【G1】用 adaptive-video-production 当写词子任务。
读 {{快照绝对路径}}、{{单元卡路径 单元\U01–U03.md}} 和 {{说明\U01–U03_说明.md}}，只写这几个单元的专属部分并拼好正文；正文写回单元卡，分析和版本记录写回说明。
单元卡格式按 references/auto-production-table.md 第 3 节。不改快照和共享块，发现快照有问题写进说明里的“待总控”。不需要和用户讨论，写完即结束。
```

用户回来说“写完了”，总控直接读文件继续检查，不需要用户转述内容。

### 总控自己也会变长

总控自己很难感觉到“开始遗忘”，所以按两个硬时刻触发：对话被自动压缩过一次；或 E 轮结束、准备进入下一轮时对话已经很长。到这两个时刻，总控必须先把当前进度写进台账，再提醒：“这个对话已经很长了，建议新开一个总控，发这句话：……”。给出的那句话就是继续已有项目的开场话术，带上项目文件夹路径。因为所有东西都在文件里，换总控不会丢信息。
